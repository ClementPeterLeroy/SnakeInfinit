# v1.2.1 — Startup Repair & Windows Release

Focused maintenance update; V1.2 gameplay and challenge rules are unchanged.

- Startup: persistent diagnostics, timestamp-based playback, a brief final-frame
  hold, responsive events, and menu fallback after decoder errors.
- Distribution: local Windows x64 onedir builds, official executable icon/version,
  a console diagnostic variant, and a console-free release.
- Assets: a shared source/frozen resolver independent of the working directory.
- Profiles: `%LOCALAPPDATA%/SnakeInfinite/`, with copy-only legacy migration.
- Troubleshooting: rotating logs remain accessible without a console window.

## Diagnosis

The supplied file is `assets/px/SnakeInfinite_Startup.mp4`, not the name
`SnakeInfinite_Startup_6s.mp4` mentioned in the patch brief. The existing loader
already selected the supplied file, used a working-directory-independent path,
and invoked playback from `Application.run()` before rendering the menu.

Inspection found PyAV 17.1.0 in `.venv`, but **absent from `.venvsnake`**, where
Pygame was installed. That environment could not import the decoder and went
through the existing menu fallback. Its warning was console-only. The system
Python 3.14 environment also lacked application dependencies.

PyAV was installed into `.venvsnake`. New logs identify the interpreter, frozen
status, working directory, resource root, selected file, decoder version, stream,
first frame, frame counts, and menu transition. Preferred and legacy filenames
are supported without renaming or replacing the approved video. The supplied
six-second MP4 is silent; embedded audio in a different video remains unsupported.

Only runtime assets are bundled. Profiles/logs do not default to `_internal`.
Migration copies missing files without deleting originals or replacing existing
profiles. Existing corrupt-record backup behavior is preserved.

Build locally with `build_windows.ps1`; publication remains manual. No staging,
commits, tags, uploads, or release publication are part of this patch.
