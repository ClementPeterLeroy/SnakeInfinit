# SnakeInfinite v1.5.0 — Analysis & Experiment Framework

This release adds scientific analysis to the existing Training Center. Classic,
Arcade, challenges, Neural Laboratory, DQN, checkpoint resumption and Arena retain
their existing behavior. Learning algorithms, the 11-input encoder, rewards and
termination rules are unchanged.

## Analysis workspace

Open AI → Training Center → Analysis. Configuration and Dashboard remain separate
tabs under **TRAINING CENTER / Train & monitor**. Model A is mandatory. Model B
defaults to **None — single model** and its checkpoint/data controls are hidden
until a model is selected. Click the model selectors to cycle actual local runs;
B cycles back to None, immediately removing its comparison data. Each model has
an independent CHECKPOINT selector populated only from saved checkpoint folders.
Both slots can select the same model and different checkpoints. Missing checkpoints
are labeled unavailable, without creating a selectable placeholder checkpoint.

The DATA selector distinguishes **TRAINING THROUGH CHECKPOINT** from **FROZEN
EVALUATION**. Training records stop at the selected snapshot, even when a journal
contains later episodes. Journal fields are used only when their actual counters
and overlapping score/length/reward records agree with the saved checkpoint.
Available evaluation files are scoped to that checkpoint; none are invented.
If no evaluation exists, the control explains that Evaluate Frozen must collect
one. Switching checkpoints returns to their saved training data; switching DATA
can then select their available evaluations. Different architectures and history
lengths are supported for analysis. Metadata shows architecture, inputs, parameter count,
last recorded episode, available record count, recorded steps, status and checkpoint.

Three chart modes share model selection, range, window, alignment and comparison
context. A is emerald and B muted blue. Enter FROM/TO and Apply, use Zoom +/−,
arrows to pan, Reset Zoom for the full extent, or scroll over the chart to zoom.
Hover reads the exact underlying record or candle, including data omitted from
the dense display. Windows/groups cycle through 25/50/100/250/500; default 100.

- **Distribution:** whiskers are the true minimum and maximum, the box runs from
  Q1 to Q3, the horizontal line is the median, and the toggleable dot is the mean.
  These are not Tukey whiskers. Episode groups use fixed absolute boundaries
  (1–100, 101–200, etc.). Clipping a range clips its boundary groups too. The tooltip
  reports actual included episode range, sample count and all statistics; an
  incomplete group is never padded. Comparison candles are paired horizontally.
- **Mean / Median:** means and medians come from actual trailing raw scores,
  including records before the visible left boundary. Early windows use available
  samples. Toggle either series; means are solid and medians dashed.
- **Raw Scores:** individual episode scores. Dense rendering retains original
  local extrema and x coordinates; it never replaces values with averages.

Episode alignment uses actual episode numbers. Environment-step alignment uses
recorded cumulative counters and separate remembered range limits. Distribution
then uses fixed equal step intervals (STEP BIN, default 25,000), not estimated
episode-to-step conversions. Legacy histories missing counters disable this option.
Rolling windows continue to count completed episodes under either alignment.

## Statistical conventions

All summaries, CSV rows and hover calculations use raw records. For sorted values,
quantile position is `h = (n - 1) * p`; interpolate linearly between adjacent values
(type 7). Standard deviation divides by n (population, `ddof=0`). Empty metrics are
N/A; singleton deviation and IQR are zero. Tied best scores choose the first episode.

The selected-range panel includes n, mean, median, min, max, Q1, Q3, IQR, deviation,
apples, mean/median length, collision/stagnation percentages, mean reward, best
episode, recorded gameplay steps and duration where available. Missing fields
remain N/A; percentages require reasons for the entire selected sample. Range
steps sum recorded lengths, not display points. Duration currently requires a
range starting at episode 1 and an actual final elapsed value; cropped ranges
show N/A. Intermediate elapsed values are unnecessary for a recorded total.

Training histories contain epsilon exploration: they describe learning behavior,
not definitive learned-policy rankings. Mixed training/evaluation overlays are
rejected. Models with different input dimensions can share analytical views;
execution still requires the implemented baseline encoder.

## Frozen evaluations

Select saved checkpoints (including two from the same run), set GAMES and initial
SEED, then Evaluate Frozen. Presets cycle 25/100/500; custom accepts 1–10,000.
The seed list is the consecutive explicit range starting at SEED. Work runs in
the background with progress; click again to cancel safely. No partial result is
published on cancellation.

Evaluation loads independent frozen models and reuses Arena's greedy inference
with no epsilon or optimizer updates. Both models receive the first selected
checkpoint's explicit reward/termination configuration and identical seeds. The
result JSON records that shared configuration and every seed, score, length,
reason, return and actual cumulative evaluation step count. EVAL entries become
available in the selectors. Comparisons require matching recorded seed lists and
settings. Select existing results through each checkpoint's DATA control.
Different training architectures are permitted when their encoder is
compatible. Evaluation never changes checkpoints or training journals.

## Persistence and legacy compatibility

Storage remains in the existing user-data profile. New directories:

| Directory | Contents |
| --- | --- |
| `history/` | Version-1 SQLite WAL journal, runs, episodes and optimization traces |
| `evaluations/` | Separate frozen result JSON files |
| `exports/` | Unique CSV files and calculation metadata sidecars |
| `experiments/` | Immutable experiment JSON plus append-only linkage events |

Every new completed episode appends a transaction containing its run ID, number,
score, length, return, reason, cumulative steps, epsilon and elapsed training time.
Optimizer loss/gradient/epsilon records are buffered in batches of at most 256
steps and flushed at episode boundaries and shutdown; the last partial batch can
be lost on abrupt process termination. Episode transactions use SQLite durability.
Journal failures show a warning and stop further journal writes for that session;
training continues independently. Resume creates a separate append-only analysis
session, avoiding conflicting records when branching from an older checkpoint.

v1.4 checkpoint folders remain unchanged. They hold at most 20,000 raw scores,
lengths and rewards and 2,000 loss/epsilon samples inside `training.pt`. Per-episode
reasons, cumulative steps, epsilon and elapsed times were never saved; only final
values can be recovered. Available episode numbers reflect the retained tail,
not fabricated history starting at 1. Classic scores record actual apple counts.
There is no automatic migration or production-data rewrite.

New journal and evaluation loading needs no neural weights. Legacy histories
share a monolithic tensor file with replay/optimizer tensors, so read-only,
checksum-verified `weights_only=True` deserialization is necessary; no network is
constructed just for history. This is bounded and performed off the UI thread.
An already-running v1.4 process keeps its original loaded code; v1.5 does not add
missing journal fields retroactively to that process.

## Exports and experiments

**EXPORT RAW** writes one row per episode with model/run identity and available
fields. **EXPORT GROUPED** writes exact group statistics and actual sample counts.
RANGE is the default; toggle FULL to export full history. Both selected models are
included. UTF-8 preserves Unicode names, missing values are blank, floats use
12 significant digits. A JSON sidecar records range, identities, limits, grouping
and statistical conventions. Unique exclusive creation prevents overwriting;
write failures are reported without stopping training. Filenames identify model
name, checkpoint episode/identity and type, for example
`snakeinfinite_baseline-dqn_10000ep_raw.csv` or
`snakeinfinite_baseline-dqn_10000ep_grouped-100.csv`. Checkpoint folder identities
add their short saved ID (such as `10000ep-aabbccdd`), frozen datasets add `-eval`,
and comparisons join both model/checkpoint identities with `_vs_`. Names exclude
Windows-invalid characters, have bounded length, and repeated requests add `-2`,
`-3`, etc. The selected checkpoint determines the name, not the last visible or
evaluated episode. Metadata sidecars retain full checkpoint paths and episode counts.

Experiment metadata includes ID/name, encoder, input count, architecture,
hyperparameters, rewards, training seed, evaluation seeds, environment-step budget,
runs, checkpoints and result links. New training sessions register Experiment A
automatically; the Analysis button can record a baseline plan for selected data.
Budgets are recorded plans, not changes to DQN's existing episode target. Checkpoint
and evaluation associations append events without rewriting experiment descriptions.

| Experiment | Inputs | Status |
| --- | ---: | --- |
| A: Baseline | 11 | Executable existing encoder |
| B: Food Awareness | 13 | Future research; relative food coordinates |
| C: Obstacle Awareness | 16 | Future research; directional distances |
| D: Survival Awareness | 19 | Future research; reachable-space estimates |

Generic metadata supports future dimensions; B/C/D observations are not implemented.

## Responsiveness and manual checks

Catalog loading, history deserialization, statistics, exports and evaluations use
background workers. Four cached derived bundles are retained. Journal/WAL/result
signatures are checked every three seconds while Analysis is active; changed data
reloads without resetting context. Chart drawing uses cached bounds and at most
600 extrema-preserving line points per series or about 280 actual candles.
Dense candle views explicitly sample original candles rather than average their
quartiles; zoom to inspect individual groups. Exact hover/export retain all data.
Analysis display failures are caught at the Training Center boundary.

1. Launch `python main.py` from the project with optional AI requirements installed.
2. Open Training Center; check all three tabs, title, labels and resized-window fit.
3. Select the final v1.4 checkpoint. Verify available raw history and missing-field
   explanations. Check grouping, exact hover, incomplete groups and all modes.
4. Add a second model; zoom, pan, crop, switch modes and verify context is retained.
5. Evaluate two checkpoints on 25 identical seeds. Check progress/cancel, separate
   EVAL entries and statistics. Export both raw and grouped range/full CSVs.
6. Start a small disposable new run using temporary settings/profile. Check compact
   Dashboard epsilon, journal refresh, pause/resume, checkpoint/Lab/Arena and errors.
7. Play Classic, Arcade and challenges; verify optional-Torch fallback separately.

Automated tests render using dummy SDL. Actual desktop appearance, audible playback
and subjective smoothness require these manual checks; they are not claimed from
headless tests. See [validation](../analysis-validation.md) for measured results.
