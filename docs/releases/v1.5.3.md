# v1.5.3 — Parallel Frontier Training

Frontier supports **1/2/4/8 independent environments**, using either an ordered
vectorized collector or Windows-spawn workers. All environments feed one shared
DQN learner and replay buffer, with batched MLP/CNN policy inference. The original
A/B/C/D architectures, encoders, rewards and learning objective remain unchanged.

Configuration adds environment count, Auto/vectorized/multiprocessing selection,
and an explicit optimizer schedule. **One update per transition** is the reference.
**One update per vector step** collects more data per update and is labeled as
fewer updates. Auto resolves to vectorized; the conservative default remains one
environment because larger counts do not consistently improve reference-policy
learning throughput in the measured CPU matrix.

Global counters, seed derivation and ordered completions make runs reproducible
within a fixed configuration/runtime. Exact episode targets avoid overshoot.
Parallel checkpoints restore partial episodes from seed/action traces, with shared
learner, replay, optimizer and RNG state. Pause/save does not advance episodes;
stop/final completion releases children. Failed collectors report errors and
attempt a recovery checkpoint without counting incomplete responses. Historical
single-environment checkpoints remain readable and resumable.

The dashboard displays actual collector settings, active environments and health,
actual optimizer counts, CPU/RAM, readable elapsed duration and a smoothed recent
completion-rate ETA. Analysis retains its interface and frozen evaluation semantics;
raw CSV adds environment identity and local sequence when recorded.

The release benchmark covers **160 trials**, separating simulation and learning
across all four models, counts and strategies, with equal-data and equal-update
budgets. No worker failures occurred. Eight-environment vector-policy collection
reached about 3,772 original-MLP steps/s and 382 ordered-CNN steps/s in short runs;
those 512-transition runs performed only 57 updates versus 449 for the reference
policy. These are different learning budgets, and no policy-quality improvement
is claimed. Multiprocessing overhead generally makes vectorized collection the
better default for this lightweight simulation.

The final automated suite passes **431 tests**. Startup and offscreen UI checks
pass, both historical completed models load, and 159 protected historical files
remain unchanged.
