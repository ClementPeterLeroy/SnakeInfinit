# v1.4.0 — First Intelligence

One integrated release adds **NEURAL LABORATORY — Build & inspect**,
**TRAINING CENTER — Train & monitor**, and **ARENA — Watch & evaluate**. Mandatory
subtitles sit beneath the AI menu titles, using the existing branding and palette.
Classic, Arcade, five challenges, official assets, startup video, records and all
Neural Foundations Step/Live/inspection/editing features are preserved.

## DQN and training

CPU online/target networks use the existing default 11→16→8→3 architecture (355
parameters), raw Straight/Left/Right action values, uniform bounded experience
replay, epsilon-greedy exploration, Huber loss, Adam and gradient clipping.
Defaults: 10,000 episodes, learning rate 0.001, gamma 0.99, batch 64, replay
100,000, linear epsilon 1→0.05 across 100,000 steps, target sync every 1,000 steps,
checkpoint every 500 episodes, clip norm 10 and training seed 0.

Configurable rewards are apple +10, collision −10, normal movement −0.01 and
stagnation −5. A separate wrapper bounds training/evaluation episodes with
100×body-length no-food steps and a 10,000-step absolute cap. Collisions and board
completion terminate; stagnation/cap truncate. Both close the explicitly finite
episodic return without bootstrapping. There is no distance reward/turn penalty,
and these limits never change ordinary arcade or laboratory Live rules.

The configuration supports a new architecture, current lab model or saved lab
weights. The worker owns all training tensors; rendering consumes immutable
snapshots. Dashboard controls provide Start, Pause/Resume, Stop, Save Checkpoint,
View Speed, Open in Arena and Inspect in Lab. Real-time, 2×/5×/10×/20× accelerated,
and headless views expose actual metrics, four bounded/downsampled charts, and
measured throughput. Pauses retain the current episode. Numerical failures stop
visibly rather than resetting weights. New runs/replacements require confirmation.

## Checkpoints and evaluation

The shared model library groups unique checkpoints beneath each training run.
JSON identity/configuration and safe weights-only tensor files store online and
target models, Adam, replay/cursor, dedicated RNG states, counters and histories.
Initial, interval, completion and pending manual saves use episode boundaries.
Existing checkpoint paths are never overwritten; manual mid-episode saves remain
pending until the next boundary, requiring Resume if paused. A resumed run restores
its saved hyperparameters/epsilon; only its episode target may be extended.

Arena loads a separate frozen model for greedy, exploration-free evaluation.
Its dominant board and HUD show model/episode, score, simulation time, steps,
direction and session best/games/average/last termination. Controls include
Play/Pause/Resume, same-seed Reset, New/Next Game, speed 1×/2×/5×/10×, editable
seed, optional delayed Auto Next, model selection and Back. It never optimizes.

Trained checkpoints also open as independent editable laboratory copies with
model name, training episode, architecture, actual neuron values, Step/Live and
forward/gradient inspection. Experiments cannot overwrite the original checkpoint;
save a separate lab model to retain edited weights. All AI dependencies remain
optional and excluded from the existing lightweight arcade executable.

## Validation

The original **282 tests** remain, with the identity assertion following v1.4.
New coverage includes DQN/exploration/replay/targets/clipping, reward and episode
limits, full-state exact resume, corruption rejection, worker commands/shutdown,
frozen Arena controls, UI configuration and cross-view checkpoint loading.
Final full suite: **319 passed, 0 failed, 0 skipped** with CPU Torch installed.
With Torch made unavailable: **201 passed, 0 failed, 7 skipped**; the seven skipped
entries are the Torch-dependent test modules. All three AI entry points degrade
gracefully, while ordinary arcade/headless checks still execute.

A real **300-episode CPU experiment** completed **49,329 steps in 79.69 seconds**
(**3.76 episodes/s**, **618.99 steps/s**). Across fixed evaluation seeds 0–19,
mean score rose from **0.0 to 3.5** after safe checkpoint reload. Fourteen trained
games stagnated and six hit the absolute cap: this is initial learning evidence,
not mastery. See [the reproducible validation report](../training-validation.md).

The AI menu, both configuration pages, actual real-time/headless dashboard,
Arena selection/board and trained laboratory were rendered offscreen and inspected.
This does not claim audible speaker output, a full human usability session or a
new AI-enabled executable. Existing dist binaries are unchanged; run AI from source.

## Manual checklist

1. Run from source with AI dependencies installed. Verify all three menu titles
   and subtitles; separately launch all seven human modes without Torch.
2. Configure a short run (e.g. 10 episodes), verify parameter count and validation
   errors, and Start. Watch actual movement/episode resets in real time.
3. Cycle accelerated speeds and headless. Check actual throughput, metrics and
   all four charts. Pause/Resume/Stop without losing in-memory progress.
4. Request a mid-episode checkpoint and observe pending status. Resume to finish
   that episode. Check interval/completion checkpoints in the grouped library.
5. Select a saved run/checkpoint and resume with a larger episode target. Verify
   epsilon/completed counts continue rather than reinitialize.
6. Open the saved checkpoint in Arena. Check greedy playback, speed, pause,
   editable seed/same-seed Reset, New Game, terminal reason, Next Game, session
   statistics and delayed Auto Next. Resize and close normally.
7. Inspect the checkpoint in Lab, use Step/Live, select neurons and alter a
   parameter. Reload the saved checkpoint to verify experiments did not alter it.
8. Close while training is active and verify the worker stops safely. Save before
   closing if you need progress newer than the latest boundary checkpoint.

## Limits and next milestone

CPU/Classic/11-feature observations only. Replay and training snapshots are bounded;
large capacities increase memory and checkpoint size. History charts retain a
recent window, while aggregate counters cover the full run. Exact resume is
runtime-specific. Checkpoints must be trusted local files; checksums are not
authentication. Paused mid-episode save requests need Resume to reach a boundary.
No GPU, online services, advanced DQN variants or guaranteed training success.

Next: **v1.5**, deeper diagnostics, learning curves, architecture comparisons and
advanced evaluation. No staging, commits, pushes, tags, GitHub releases or publishing
were performed for this release.
