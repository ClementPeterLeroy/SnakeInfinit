# v1.5.3b — Recovery Repairs & Model Library

This release repairs the two confirmed parallel-training audit defects and adds
one shared model-management workflow. The four architectures, CPU DQN behavior,
learning defaults and existing research roadmap are preserved.

- **Safe recovery:** incomplete vector batches cannot publish resumable checkpoints.
  Active traces are validated before saving. Failure feedback distinguishes a new
  verified checkpoint, the previous verified checkpoint and unavailable recovery.
- **Durable completion history:** committed events drain on failure and persist
  exactly once. A local emergency journal covers SQLite flush failure and remains
  readable by Analysis. No exact optimizer rollback is claimed.
- **Model Library:** Alpha / Distance / CNN / oCNN generations have immutable IDs,
  independently increasing family numbers and optional descriptions. Resume retains
  identity; independent training allocates a new generation.
- **Shared selection:** Frontier, supported Legacy training, Arena, Analysis/frozen
  evaluation and the Alpha Laboratory use Family → Generation → Checkpoint.
  Inference-only exports are distinguished from full training continuation.
- **Conservative indexing:** original artifacts stay in place and unchanged.
  Proven lineage is grouped; unavailable or ambiguous provenance is marked for review.
- **Reversible management:** deletion previews, loaded/active guards, ownership/path
  checks, shared-record retention, journaled Trash and Restore protect existing data.

See [library usage and design](../model-library.md) and
[validation, migration results and limits](../v153b-validation.md). The historical
[v1.5.3 audit](../audits/v1.5.3-parallel-frontier-audit.md) records the original
