# SnakeInfinite v1.5.1 — Frontier Training Foundations

Frontier adds a performance-oriented execution and presentation pipeline around
the existing CPU DQN. Architecture, observation encoder, replay sampling, exploration,
target synchronization, rewards, Adam/Huber updates and episode rules are unchanged.

## Navigation and configuration

AI → Training Center offers **LEGACY TRAINING** and **FRONTIER TRAINING**. Legacy
retains its Configuration, Dashboard, Analysis, checkpoint selectors, evaluation
and CSV exports. Frontier has Configuration, Dashboard and shared Analysis tabs.
Existing programmatic `open_training` routing continues to open Legacy directly.

Frontier supports new 11-input networks, the current Laboratory network, saved
models and resumable checkpoints. Default budget is 10,000 episodes, seed 0.
Dashboard refresh cycles 25/100/500 completed episodes, default 100. The execution
label is read-only **CPU / 1 environment**. Headless is enabled by default; disabling
it selects paced headless execution at roughly 9 steps/s, without a board display.
No nonfunctional CUDA or worker-count controls are exposed.

Advanced pages expose existing learning-rate, gamma, replay/batch, epsilon schedule,
target synchronization, rewards, clipping, episode limits, hidden sizes and activation.
Recovery interval and retained slot count are separate execution policy settings.
Resume restores saved learning settings, architecture, optimizer and RNG streams;
only the target episode count may be extended. Invalid settings are rejected before
the worker begins. Starting another experiment requires pausing/stopping the current
session, and always creates a new isolated directory.

## Execution and Dashboard

The worker owns all tensors and calls the original `Trainer.train_step()`. It never
imports Pygame, draws a board, plays sounds or runs game animations. Presentation
receives detached metric/chart snapshots at the chosen episode interval, on control
changes, errors and completion. No per-step training state is copied into the UI.
Headless commands are polled at boundaries or at most every 32 movement steps;
paced mode polls each step. Responsiveness depends on actual step/serialization time.

Every episode is recorded even when no Dashboard refresh occurs. Redundant per-step
loss writes are replaced with per-episode update counts, mean/last loss and final
gradient norm. The actual optimizer and replay operations are never skipped to
increase throughput. Journal transactions batch up to 25 completed episodes and
flush on refresh, pause, save, completion and orderly shutdown.

Dashboard displays completed/target, percentage, last-100 mean and median score,
all-run best, environment steps, achieved steps/s, episodes/s, optimizer updates/s,
cumulative active elapsed time and ETA. Diagnostics include epsilon, Huber TD loss,
apples, collision/stagnation counts and percentages and recent-100 mean/median
episode lengths. Process CPU uses 100% for one logical core; RAM/peak working set
are measured on Windows. Unavailable platform measurements show N/A. These process
measurements may include other activity inside the same application.

Four charts show true-min/max distribution candles, raw rolling mean/median, last
recorded episode loss and throughput against actual active seconds. Score charts
use the existing type-7 linear quartiles and population deviation. Display history
is bounded to the last 20,000 score records/2,000 loss points; the disk journal
retains all completed episodes. Throughput is a cumulative session average, not a
requested playback multiplier. Full Dashboard surfaces are cached between snapshots.

## Controls and resumption

- **START:** validate, allocate a unique experiment and start the worker.
- **PAUSE / RESUME:** retain the exact in-memory partial episode and optimizer state.
- **STOP:** pause and offer **FINISH EPISODE & SAVE / STOP**, **STOP / KEEP IN MEMORY**,
  or cancel/resume. Finishing may advance through the remaining bounded episode.
- **SAVE CHECKPOINT:** request the next completed-episode boundary. If paused during
  a partial episode, resume to reach that boundary; a boundary can save immediately.
- **OPEN IN ARENA:** load an independent frozen copy of the last saved artifact.
- **OPEN EXPERIMENT FILES:** open the actual output directory in the OS file manager.

Closing flushes collected episode records but does not serialize a partial episode.
Use Stop → Finish Episode & Save when retaining the latest progress is required.
Disk/serialization failures are visible; a failed final save is not called Completed
and can be retried through Save Checkpoint. Recording failures stop the worker with
an error rather than silently dropping research records.

## Artifacts and checkpoint policy

Default source output is visible in the repository at
`experiments/frontier/<experiment-id>/`. Configuration shows an editable absolute
path. Custom settings profiles and packaged launches default beside their settings.
An exclusive writer lock and unique directory prevent sessions sharing a destination.
Old baseline directories are never overwritten or migrated.

| Episode | Artifact |
| --- | --- |
| 1,000 / 3,000 / 5,000 / 10,000 | Lightweight model snapshot, if within the budget |
| Configured recovery interval (default 1,000) | Resumable recovery; default last two retained |
| Actual final episode | Final lightweight model and full resumable checkpoint |

A final target equal to a milestone uses its final artifact instead of duplicating
that milestone. Longer/shorter budgets always save their real final target. Only
recovery checkpoints in the newly created experiment are rotated; milestones and
final models are retained. Artifact paths and policy are recorded in manifests.

`models/snake_dqn_11_ep010000_model.pt` contains original weights only; its matching
JSON supplies architecture, feature/action order, checksum, episode and identity.
These are suitable for GitHub sharing and are actually reloaded/validated before a
save is reported successful. See [experiment files](../../experiments/README.md)
for the loading API. Full checkpoint/history folders are ignored at the default
repository location; model exports remain available for manual Git operations.

The canonical checkpoint folder contains online weights/configuration, target
weights, Adam state, replay contents/cursor/RNG, exploration/environment/Torch RNG
states, counters, epsilon schedule configuration, histories and experiment/encoder
metadata. `snake_dqn_11_ep010000_checkpoint.pt` is a descriptive alias/copy of
`training.pt`, not a standalone bundle. Keep the whole folder.

Checkpoints are **completed-episode boundary snapshots**. Environment/replay
transitions are complete; the next episode is recreated from the restored owned
environment RNG. No partial environment is restored or claimed. Exact continuation
is tested under the same CPU/runtime. Existing v1.4/v1.5 resumable checkpoints remain
readable. Model-only milestones explicitly reject training-resume requests.

Metadata commits and recovery-pointer replacement are atomic; recovery pointers
advance only after validation. An interrupted save leaves the previous recovery
usable; incomplete folders without committed metadata are not catalog entries.
This protects against interrupted serialization, not every possible storage failure.

## Research records and interoperability

Experiment JSON records identity, encoder, architecture, seeds, learning/execution
settings, parent checkpoint and declared maximum step budget. The existing generic
experiment framework also records checkpoint/evaluation associations. A profile index
registers new libraries so Legacy/Frontier Analysis and Arena can discover them.

The version-1 episode journal retains `run_id` (the experiment ID), episode, actual
environment seed, score, length, cumulative steps, reward, reason, epsilon, active
elapsed time and apples. A separate episode diagnostics table records optimizer
updates, mean/last loss and gradient norm. Full raw records remain available to the
existing Analysis/CSV system; no grouped values replace observations. Frontier
training histories are clipped to selected checkpoints and remain distinct from
frozen evaluations. Pause/refresh/save/final flush pending records; abrupt termination
may lose the last unflushed batch of at most 24 completed episodes after the last
committed transaction. Recovery checkpoints flush first and resume from their own
documented boundary. Resuming creates a new experiment without rewriting old history.

## Profiling and measured performance

Profiling is opt-in. Exclusive timers report environment stepping, state encoding,
inference, replay sampling, forward/backward work, optimizer updates, metrics
aggregation, serialization and UI synchronization. Disabled profiling installs no
timing wrappers. Zero calls means that phase was not exercised in the sample.

The controlled worker comparison used the same 11→16→8→3 network, initial weights,
seed 7, hyperparameters and exactly 100,000 environment steps in sequential isolated
processes. Legacy and Frontier achieved **587.7 / 634.1 steps/s**, respectively;
this single pair measured **7.9% higher Frontier throughput**. All transition hashes,
final online/target weights and 99,937 optimizer-update counts matched. The historical
131 steps/s baseline is not a controlled comparison and is not used for a speedup claim.

See [validation and reproduction](../frontier-validation.md) for wall-clock/RAM,
final statistics, profiling, tests, limitations and manual checks. Forward/backward
and optimizer work remain the main bottleneck. Vectorized environments, CUDA,
spatial CNNs and Benchmark Laboratory features remain future releases.

The planned roadmap reserves v1.5.2 for parallel/vectorized environments and batched
inference, v1.5.3 for CUDA/device selection, v1.5.4 for further Frontier optimization
and validation, v1.5.5 for Benchmark Laboratory, and v1.6.0 for spatial neural research.
None of those capabilities is implemented or exposed as a working control here.
